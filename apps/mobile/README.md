# Wrap CalendarX for Android (Capacitor + signed-APK CI)

Generated by @calendarx/mobile-wrapper. This is a reusable template — anyone can
wrap a TanStack (or any SSR/SPA) web app as a signed Android APK and publish it
through Obtainium without redoing the setup.

## Shape: monorepo (pnpm + Turborepo)

- Wrapper package: apps/mobile (capacitor.config.ts + committed android/)
- webDir: ../../apps/web/dist/client
- appId: dev.calendarx.app  appName: CalendarX
- Baked live origin: `CALENDARX_ANDROID_ORIGIN` (fallback https://calendar.xeroneon.dev)

## Native connect shell (self-hosted onboarding, XER-312)

The Android app ships a **first-class NATIVE onboarding screen** (not the webview),
because every distributed user self-hosts their own CalendarX server. Flow:

- `ConnectActivity` (launcher) lets the user paste/type their server URL. A demo
  default origin is prefilled; `Test connection` runs an in-app health check
  (`GET /api/health`, must return `name:"calendarx"`) plus `.well-known/caldav`
  discovery via `ServerProbe.kt`.
- On connect, `InstanceStore.kt` persists the verified origin with
  **EncryptedSharedPreferences** (Android Keystore backed, AES256).
- `MainActivity` (Capacitor) overrides `load()` to build a CapConfig pointing the
  WebView at the persisted origin, reusing the full web UI. The baked origin is
  only the fallback for a still-unconfigured install.

### Connect screen is first-launch only (XER-322)
Once an instance is saved, the launcher goes **straight into the calendar**:
`ConnectActivity.onCreate()` finishes into `MainActivity` before drawing if
`InstanceStore.hasInstance()` is true, so the setup screen never flashes again.
Re-configuring another instance stays reachable via a floating **"Change server"**
gear button that `MainActivity` overlays on the webview — it re-launches
`ConnectActivity` with `EXTRA_RECONFIGURE`, which forces the setup UI to show even
though an instance exists (see `MainActivity.onNewIntent` for the singleTask reload).

Kotlin sources live under `android/app/src/main/java/dev/calendarx/app/`
(`ConnectActivity.kt`, `InstanceStore.kt`, `ServerProbe.kt`). Build deps:
`kotlin-gradle-plugin` (root build.gradle), `androidx.security:security-crypto`,
`core-ktx` (app build.gradle).

## Files to land

1. `apps/mobile/capacitor.config.ts` — the rendered Capacitor config.
2. `apps/mobile/android/` — commit the native project (`npx cap add android`
   once, then commit it; CI does `cap sync` and regenerates build outputs).
3. `.github/workflows/release-android.yml` — the rendered signed-APK workflow.
   Triggers on `v*` tags + `workflow_dispatch`; stages
   `calendarx-v<ver>.apk`; mirrors to xeroneon/calendarx-releases.

## One-time setup (do NOT redo per release)

### 1. Signing keystore (never commit — CI secret only)
```
keytool -genkeypair -v -keystore ~/calendarx.keystore -alias calendarx \
  -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=CalendarX,OU=Mobile,O=Xeroneon"
```

### 2. GitHub Actions secrets on xeroneon/calendarx
- `ANDROID_SIGNING_KEYSTORE_BASE64` — base64 of the keystore
- `ANDROID_SIGNING_KEYSTORE_PASSWORD` / `ANDROID_SIGNING_KEY_ALIAS` / `ANDROID_SIGNING_KEY_PASSWORD`
- `CALENDARX_ANDROID_ORIGIN` — the LIVE origin (e.g. `https://calendar.xeroneon.dev`), NOT a dead
  placeholder. Baked at `cap sync`; wrong origin = app installs but renders nothing.
- `RELEASE_REPO_PAT` — classic PAT with `repo` scope to publish to the PUBLIC
  xeroneon/calendarx-releases from this private source repo. (GITHUB_TOKEN is repo-scoped.)

### 3. Public Obtainium channel xeroneon/calendarx-releases
- Must be a PUBLIC, release-only repo. Seed it with an initial README on main
  BEFORE the first mirror run, or GitHub 422s 'Repository is empty'.
- Obtainium source = xeroneon/calendarx-releases, "What to install" regex
  `calendarx-v[.\\\\d]+[.]apk`, Version check = By release TAG NAME.

## Build on a new machine
```
npm i  # or pnpm install
# local dev/prod web build first, then:
cd apps/mobile && pnpm exec cap sync android
cd android && ./gradlew assembleRelease
```
Without signing `-P` props, gradle falls back to the DEBUG key (still builds, not
the release cert). Verify the baked origin + signer before publishing
(`python3 scripts/verify_apk_origin.py <apk> [origin]`).

## CI pitfalls (all hit live; see skill capacitor-android-obtainium-release)
- Snapshots secrets at workflow START — change => re-trigger.
- Mark broken-origin releases prerelease so Obtainium skips them.
- npm lockfile: regenerate with the SAME npm the CI node uses (npm 10 / node 22),
  or `npm ci` rejects it (out-of-sync).
- Verify origin resolves (curl it) before trusting an APK.
